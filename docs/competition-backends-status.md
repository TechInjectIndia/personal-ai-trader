### Install method note

The system npm prefix (`/usr/lib/node_modules`) is **root-owned and not
writable** by the run user, so a global `npm i -g` would need sudo. The four
CLIs were installed into a user-local prefix instead:

```bash
mkdir -p ~/.npm-global
npm install -g --prefix ~/.npm-global \
  @google/gemini-cli @qwen-code/qwen-code @openai/codex opencode-ai
export PATH="$HOME/.npm-global/bin:$PATH"   # add to the agent runner's env
```

Anything that shells out to these CLIs (the smoke script, the future freestyle
runner) must have `~/.npm-global/bin` on `PATH`. `claude` is already on PATH at
`~/.local/bin/claude`. The adapters also honor per-backend override env vars
(`GEMINI_CLI_PATH`, `QWEN_CLI_PATH`, `CODEX_CLI_PATH`, `OPENCODE_CLI_PATH`,
`CLAUDE_CLI_PATH`) if you'd rather pin absolute paths.

## Login commands the human must run (for the NEEDS-AUTH backends)

These are **interactive OAuth flows** — an unattended agent cannot complete
them. Run each in a terminal where a browser (or device-code paste) is
reachable, then re-run `python scripts/smoke_backends.py` to confirm the
backend flips to `OK`. Prefer the **free** auth options to keep $0 spend.

## How the registry is wired

- `helm/llm.py` exposes `CLI_ADAPTERS: dict[str, adapter]` keyed by backend name.
- `complete_json(...)` / `decide(...)` take an optional `backend` argument;
  precedence is `backend` arg → `LLM_BACKEND` env → default `claude`.
- When no backend is given and `LLM_MODE` is unset/`cli`, behaviour is
  byte-for-byte identical to the previous single-backend implementation
  (the `claude` adapter, 300s production timeout). Existing callers are
  unaffected; the `api` mode path is untouched.
- The smoke script uses a fast **30s** timeout per call (never the 300s
  production timeout).
